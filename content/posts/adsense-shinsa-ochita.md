Google AdSenseの1回目の審査に落ちました。理由は「**有用性の低いコンテンツ**」です。

このブログは「知識ゼロからVPSでブログを作って、収益化までやってみる」記録なので、落ちたこともそのまま書いておきます。審査結果が出たときのブログの状態、自分なりに考えた原因、そしてやった対策です。

## 審査結果が出たときのブログの状態

| 項目 | 状態 |
|---|---|
| 記事の数 | 36本 |
| ブログを始めてから | 約1か月半 |
| 1本あたりの長さ | 短いもので1,000字台、長いもので3,000字台 |
| 検索からの訪問 | Search Consoleで、表示100回ちょっと、クリック10回ほど |
| リアルタイムの訪問者 | Analyticsを開くと、だいたい自分だけ |
| 必要なページ | プライバシーポリシー・お問い合わせ・運営者情報はそろえていた |

ページはそろえていて、記事の数も少なくはない。だから「記事数が足りない」ではなく「中身」を指摘された、と受け取りました。

## 自分なりに考えた原因

Googleは、具体的にどのページの何が悪いかまでは教えてくれません。なので、ここからは自分の推測です。

### 1. 同じテーマの記事が何本もあった

一番大きいと思ったのがこれです。数えてみると、同じことを違う切り口で書いている記事がたくさんありました。

| テーマ | 書いていた記事の数 |
|---|---|
| 記事を公開する手順 | 3本(連載の第7回、操作だけ版、流れの解説版) |
| HTTPS化 | 3本(連載の第6回、HTTPとHTTPSの違い、ハマった話) |
| WordPressとVPSの比較 | 4本(連載の第1回、レンタルサーバーとの違い、運用の違い、費用の比較) |
| Search Console | 2本(連載の第8回、導入した話) |
| Google Analytics | 2本(連載の第9回、導入した話) |

書いた本人としては「手順だけ知りたい人向け」「詳しく知りたい人向け」と分けたつもりでした。でも、読む人から見れば「どれを読めばいいのか分からない」し、Googleから見れば「中身の重なったページがたくさんあるサイト」です。

### 2. 1本ずつが薄かった

似た記事に分けたぶん、1本あたりの情報が少なくなっていました。特に連載の記事は「操作手順だけ」に絞っていたので、どこにでもある手順書に近いものになっていました。逆に、このブログにしかない「実際にハマった話」は別の記事に分かれていて、手順の記事からは見えにくくなっていました。

### 3. 審査中に、サイトが壊れていた時期があった

ちょうど審査を待っているあいだに、サイトのデザインが消えて文字だけになるトラブルが起きていました(→ [CSSが404になった原因はフォルダの権限だった](/posts/css-404-permission/))。審査は、Googleのロボットがサイトを見に来て行います。そのタイミングで来られていたら、印象はよくなかったはずです。

### 4. まだ読者がほとんどいない

検索からのクリックは10回ほどで、ほぼ誰にも読まれていない状態でした。読者の数そのものが審査の条件だとは書かれていませんが、「読まれている」という実績がない、ということではあります。

一番効きそうな1と2に、まとめて手を付けました。**似たテーマの記事を1本に統合して、手順と体験談を同じ記事に入れる**ことにしました。

### 消した記事のURLは、まとめた先に転送する

記事を消すと、そのURLは「ページが見つかりません」になります。検索結果やほかの記事からリンクされていた場合にもったいないので、古いURLに来た人は、まとめた先の記事に自動で移動するようにしました。

Hugoでは、まとめた先の記事のフロントマターに `aliases` を書くだけです。

```
+++
title = "【第7回】記事の作成編 — Hugoで書いて公開するまで"
aliases = ["/posts/kiji-koukai-saitan/", "/posts/hugo-publish-flow/"]
+++
```

こう書いておくと、`hugo` を打ったときに、古いURLの場所に「新しいURLへ移動するだけのページ」が自動で作られます。このページには「正式なURLはこちら」という印(canonical)も付くので、Googleにも新しい記事が正しいページだと伝わります。また、移動するだけのページはサイトマップには載りません。

## まとめてみて気づいたこと

- 同じことを、違う記事で3回も説明していた。まとめると、繰り返しの部分がごっそり消えた
- 「手順」と「ハマった話」が同じ記事にあると、手順のどこで何に気をつければいいかが分かりやすい
- このブログにしかない情報は、手順ではなく「実際にハマった話」のほう。そこを厚くするべきだった
- 記事が多いほど良い、ではない。読む人が迷わないことの方が大事

## これからやること

- **体験談を中心に記事を増やす**。手順だけの記事は、もう書かない
- 書くときに「この内容、すでにどこかの記事に書いていないか」を先に確認する
- Search ConsoleとAnalyticsで、読まれている記事を見て、その記事をさらに厚くする
- 12月ごろを目安に、もう一度AdSenseに申請する
