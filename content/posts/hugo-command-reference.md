Hugoを触り始めてから、同じコマンドを何度も打っているうちに「これ何のためのコマンドだっけ」と忘れることが多かったので、意味と使うタイミングを一覧にまとめておきます。

## 前提:コマンドはどこで打つのか

すべて、**`hugo.toml`があるフォルダ(プロジェクトのルート)まで移動してから**実行します。

```powershell
cd "C:\Users\user\...\yourlog-site"
```

`hugo`から始まるコマンドを打って`Unable to locate config file`というエラーが出たら、大抵はこの`cd`を忘れているサインです。

## コマンド一覧

| コマンド | 意味 | 使うタイミング |
|---|---|---|
| `hugo new site フォルダ名` | 新しいHugoサイトの骨組みを作る | 最初にサイトを立ち上げるとき、一度きり |
| `hugo new posts/ファイル名.md` | 新しい記事ファイルを、決まった書式(Front Matter)付きで自動生成する | 新しい記事を書き始めるとき |
| `hugo server` | 手元のPCだけで見られるプレビュー用サーバーを起動する | 記事やデザインの変更を、公開前に確認したいとき |
| `hugo`(オプション無し) | 本番公開用の完成品(`public`フォルダ)を生成する | 記事が書き終わって、実際にサーバーへアップロードする直前 |
| `hugo --minify` | `hugo`と同じだが、HTML/CSSの無駄な空白などを削って軽量化する | 本番公開時、こちらを使うとページの読み込みが少し速くなる |

## `hugo server`と`hugo`の違い(混同しやすいポイント)

これが一番間違えやすいポイントでした。

| | `hugo server` | `hugo` |
|---|---|---|
| 保存先 | メモリ上(ディスクは更新されない) | `public`フォルダに書き込まれる |
| 見られる範囲 | 自分のPCだけ(`localhost:1313`) | 誰でも見れるわけではなく、あくまでファイルを生成するだけ |
| 実際に世界に公開するには | このコマンドだけでは公開されない | 生成された`public`フォルダを、別途サーバーに転送する必要がある |

**`hugo server`は毎回`public`フォルダを更新するわけではない**、という点を最初理解しておらず、「保存したのに変わらない」と勘違いしたことがありました。プレビュー確認は`hugo server`、実際に公開するファイルを作るのは`hugo`、と役割がはっきり分かれています。

## サーバー停止のコマンド

| 操作 | 意味 |
|---|---|
| `Ctrl + C` | `hugo server`を停止する(ターミナルにフォーカスした状態で押す) |

## 覚え方のコツ

- 「**s**erver」の`s`は「**s**ee(確認する)」の`s`だと思うと覚えやすい → 確認したいときは`server`を付ける
- 何も付けない`hugo`は「完成品を**出荷**する」イメージ

この2つさえ区別できれば、Hugoの基本操作はほぼ迷わなくなると思います。
