これまで何度もコピペで使い回してきた、Nginxの設定ファイルの中身を、改めて1行ずつ理解しておきたくなったので整理します。

## 今回使っている設定ファイル全体

```nginx
server {
    listen 80;
    server_name noluckblog.com www.noluckblog.com;
    root /var/www/yourlog/public;
    index index.html;
}
```

これだけの短いファイルですが、実はそれぞれの行に明確な役割があります。

## 1行ずつの意味

### `server { ... }`

「ここから1つのWebサイトの設定です」という、まとまりを表す枠です。1台のサーバーの中に複数の`server { }`を並べることで、複数のサイトを1台で運用することもできます(今回は1つだけ)。

### `listen 80;`

**どのポート番号で通信を受け付けるか**の指定です。`80`はHTTP(暗号化なし)の標準ポートです。HTTPS化した後は、Certbotが自動的に

```nginx
listen 443 ssl;
```

という行を追加してくれています。`443`はHTTPS(暗号化あり)の標準ポートです。

### `server_name noluckblog.com www.noluckblog.com;`

**どのドメイン名でアクセスされたときに、この設定を使うか**の指定です。ここに書かれていないドメイン名でアクセスされた場合、Nginxはこの設定を使いません(別の`server { }`があればそちらを、なければデフォルトの挙動になります)。

`www`ありとなし、両方書いているのは、どちらの書き方でアクセスされても同じサイトが表示されるようにするためです。

### `root /var/www/yourlog/public;`

**実際に配信するファイルが置かれている場所**の指定です。Hugoでビルドした`public`フォルダの中身を、ここに転送してきました。訪問者が`https://noluckblog.com/posts/example/`にアクセスすると、Nginxは`/var/www/yourlog/public/posts/example/index.html`を探しに行きます。

### `index index.html;`

**フォルダだけが指定されたときに、代わりに読みに行くファイル名**です。例えば`https://noluckblog.com/`とだけアクセスされた場合、具体的なファイル名が指定されていないので、Nginxは自動的に`index.html`を探して返します。

## セキュリティグループ・ufwとの関係

以前の記事で書いた通り、この`listen 80;`(や`443`)で指定したポート番号は、**ConoHaのセキュリティグループと、サーバー内部のufw、両方で許可されていないと外部から届きません。** Nginxの設定はあくまで「サーバーの中でどう振る舞うか」のルールであり、「そもそも外部からの通信が届くか」は、また別の層の話だと切り分けて理解できるようになりました。

## エラーチェックの習慣

設定ファイルを書き換えたら、必ずこの2つをセットで実行するようにしています。

```bash
sudo nginx -t
sudo systemctl restart nginx
```

`nginx -t`は「この設定ファイル、文法的に正しいですか?」を確認してくれるコマンドです。これを挟まずにいきなり再起動すると、設定ミスでNginx自体が起動しなくなることがあるため、必ず先にチェックする習慣にしています。

短い設定ファイルですが、1行1行に明確な意味があると分かってから、初めて中身を理解して触っている感覚が持てるようになりました。
