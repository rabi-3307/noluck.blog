記事を更新するたびに何気なく打っている`scp`コマンドですが、「これが具体的に何をしているのか」を説明できなかったので、改めて整理しておきます。

## SCPとは

SCP(Secure Copy)は、**SSHの仕組みを使って、ファイルを暗号化しながら別のサーバーに転送するコマンド**です。名前の通り、SSH(Secure Shell)と同じ「暗号化された安全な通信」の技術を土台にしています。

普段使っているコマンドはこれです。

```powershell
scp -r public\* root@163.44.103.60:/var/www/yourlog/public/
```

## コマンドの構造を分解する

| 部分 | 意味 |
|---|---|
| `scp` | ファイルを安全にコピーするコマンド |
| `-r` | フォルダの中身をまるごと(再帰的に)コピーするという指定 |
| `public\*` | コピー元(手元のPCにある`public`フォルダの中身全部) |
| `root@163.44.103.60:` | コピー先の接続情報(ユーザー名@サーバーのIPアドレス) |
| `/var/www/yourlog/public/` | コピー先の、サーバー上の具体的な保存場所 |

`:`(コロン)を境に、前半が「誰の、どのサーバーに」、後半が「サーバー上のどこに」を指定している、という構造になっています。

## なぜパスワードを聞かれないのか

`scp`も内部的にはSSH接続を使っているため、**以前設定した公開鍵認証がそのまま適用されます。** パスワードなしでSSH接続できるようにした設定が、`scp`にも自動的に効いているという理解で合っています。

## SSHとSCPの関係

| コマンド | できること |
|---|---|
| `ssh` | サーバーに接続して、コマンドを実行する(対話的にログインする) |
| `scp` | サーバーとの間で、ファイルをコピーする(ログインはせず、転送だけ行う) |

どちらも「暗号化された通信路を使う」という土台は同じですが、`ssh`は「入って操作する」ため、`scp`は「ファイルを運ぶ」ためのコマンド、という役割の違いがあります。

## 転送後に毎回起きた403エラーとの関係

以前の記事で書いた通り、`scp`で転送するたびに、転送されたファイルの権限がリセットされ、Nginxから読み取れなくなる(403 Forbidden)という現象が繰り返し起きました。これは`scp`自体の欠陥というより、**転送されたファイルの所有者・権限が、転送元(自分のWindows環境)の情報を引き継いでしまい、サーバー側のWebサーバー(Nginx)が期待する権限と食い違ってしまう**ために起きていたと理解しています。

```bash
sudo chmod -R 755 /var/www/yourlog
```

このコマンドで、転送後のファイルに「誰でも読み取れる」権限を与え直すことで対応しています。

## 学び

普段何気なく実行していた`scp`コマンドですが、分解してみると「SSHの仕組みを流用した、ファイル転送専用のコマンド」というシンプルな正体でした。仕組みを理解してからは、権限エラーが起きる理由にも納得感を持って対応できるようになりました。
