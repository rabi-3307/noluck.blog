サイトを公開した後、検索エンジンに見つけてもらうための最初の一歩として、Google Search Consoleを導入しました。単純な登録作業のはずが、想像以上にトラブルが続いたので記録しておきます。

## Search Consoleとは何か、なぜ必要か

Search Consoleは、**自分のサイトがGoogleにどう見えているかを確認できる無料ツール**です。

- サイトの構造をGoogleに伝える(サイトマップの送信)
- どんな検索キーワードで、何回表示・クリックされたかが分かる
- ページにエラーがあれば通知してくれる

ブログを「書く」だけでなく「読んでもらう」ためには、実質必須の登録だと考えています。

## ステップ1:プロパティの登録

[Search Console](https://search.google.com/search-console)にアクセスし、自分のドメインを登録します。ここで最初の選択がありました。

- **ドメイン**:`noluckblog.com`全体をまとめて登録する方式
- **URLプレフィックス**:`https://noluckblog.com/`のように、プロトコルを含めて登録する方式

「ドメイン」の方が`http`と`https`、`www`ありなしを全部まとめて管理できるとのことで、こちらを選びました。

## ステップ2:所有権の確認(DNS認証)

「これは本当にあなたのサイトですか?」を確認するため、DNSにTXTレコードを追加するよう求められました。

```
google-site-verification=(発行された文字列)
```

これを、ドメイン管理会社(お名前.com)のDNS設定画面で、**TYPE:TXT**として追加しました。以前ドメイン取得時にAレコードを追加したのと同じ画面での作業だったので、迷わず進められました。

設定後、「確認」ボタンを押すとすぐに

```
所有権を確認しました
```

と表示され、ここは特に問題なく完了しました。

## ステップ3:サイトマップの送信(ここから長いトラブル)

サイトマップ(`sitemap.xml`)は、Hugoがビルドのたびに自動生成してくれるファイルです。Search Consoleの「サイトマップ」メニューから、`sitemap.xml`と入力して送信しました。

ここで最初のエラーが出ました。

```
サイトマップ アドレスが無効です
```

実際に`sitemap.xml`を開いてみると、中のURLがすべて

```
https://example.com/posts/...
```

という、サイト構築時の**仮のドメインのまま**残っていました。原因は`hugo.toml`の`baseURL`という設定項目が、初期値のまま書き換えられていなかったことでした。

`baseURL`を実際のドメインに修正したところ、今度は**別の問題(ファイルの文字コードが壊れる事件)**に遭遇しましたが、それは長くなるので別記事に譲ります。

修正後、サイトマップの中身は正しく`https://noluckblog.com/...`になりましたが、それでもまだ

```
取得できませんでした
```

というステータスが表示され続けました。

## 本当の原因:HTTPS未対応だった

ブラウザで直接`https://noluckblog.com/sitemap.xml`にアクセスしてみたところ、「接続できません」というエラーになりました。**サイト自体がまだHTTP(暗号化なし)でしか公開されておらず、`baseURL`はHTTPSを前提にしていた**という、ちぐはぐな状態が原因でした。

Let's EncryptでSSL証明書を導入し、サイトを`https://`で公開できるようにした後、改めてサイトマップを送信したところ、ようやく

```
✓ サイトマップは正常に処理されました
検出されたページ数: 23
```

と表示され、無事に完了しました。

## つまずきポイントのまとめ

| つまずいたこと | 原因 | 学んだこと |
|---|---|---|
| 所有権確認自体はスムーズだった | ドメイン管理画面でのDNS設定に慣れていた | 一度経験した作業(TXTレコード追加)は2回目以降スムーズになる |
| サイトマップが無効と言われた | `baseURL`が仮のドメインのままだった | 公開直前に、設定ファイルの初期値を再確認する習慣が必要 |
| サイトマップが「取得できません」のまま | サイトがまだHTTPS対応していなかった | `baseURL`をhttpsにする前提として、SSL化が先に必要 |

Search Console自体の操作は難しくありませんでしたが、**裏側の設定(baseURL、HTTPS)が揃っていないと、入り口の登録作業でつまずく**という、地味に厄介な連鎖を経験しました。
