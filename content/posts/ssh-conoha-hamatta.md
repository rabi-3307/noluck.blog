VPSを契約して、いよいよSSHで接続しようとしたところ、想像以上に長いトラブルシューティングになりました。原因が分かってしまえば単純なのですが、切り分けに丸一日近くかかったので、同じところでハマる人のために記録しておきます。

## 症状

契約直後、手元のPCから普通に接続を試みました。

```powershell
ssh root@(サーバーのIPアドレス)
```

結果はこうでした。

```
ssh: connect to host xxx.xxx.xxx.xxx port 22: Connection timed out
```

## 切り分けの過程

「サーバー側の問題」か「自分側の問題」かを、順番に確認していきました。

### 1. サーバー自体は動いているか

ConoHaには、SSHを使わずブラウザ上でサーバーに直接ログインできる「コンソール」機能があります。これでログインを試したところ、**問題なくログインできました。** つまりサーバー自体は正常に起動していました。

### 2. SSHサービスは動いているか

```bash
systemctl status ssh
```

こちらも `active (running)` で正常。

### 3. サーバー内部のファイアウォール(ufw)は許可しているか

```bash
sudo ufw status verbose
```

`22/tcp ALLOW IN Anywhere` と表示され、これも問題なし。

### 4. ConoHa側のセキュリティグループ(クラウドファイアウォール)は許可しているか

管理画面で確認したところ、`default`というグループが適用されていて、中身は「全ポート・全プロトコル許可(All)」になっていました。一見、ここも問題なさそうに見えました。

### 5. 自分のネットワーク環境を疑う

自宅Wi-Fi、スマホのテザリング、別のノートPCと環境を変えて何度も試しましたが、**すべて同じくタイムアウト**。

### 6. 外部の第三者サービスで確認する

自分のネットワークを一切経由せず、外部から対象のポートが開いているか調べられる無料ツール(ポートチェッカー)で確認したところ、

```
Port 22 is closed
```

外部から見ても閉じている、という結果でした。ここまでで「サーバー側は正常」「自分のネットワークも無関係」という、一見矛盾した状況になりました。

## 原因:ConoHa VPS特有の仕様だった

行き詰まってConoHaのサポートページを確認したところ、答えが見つかりました。

> ConoHa VPSバージョン3.0をご利用の場合、SSHやSFTP接続を行う場合はSSH用のセキュリティグループ設定を追加する必要がございます。

つまり、**`default`グループが「全ポート許可」になっていても、それとは別に、SSH専用の`IPv4v6-SSH`というセキュリティグループを追加で割り当てないと、SSH接続自体が許可されない**という、ConoHa VPS 3.0特有の仕様でした。`default`の中身だけを見て「All許可だから大丈夫」と判断していたのが、そもそもの見落としでした。

### 対応

1. 管理画面の「セキュリティグループ」一覧に、あらかじめ`IPv4v6-SSH`という項目が用意されていることを確認
2. サーバーの「ネットワーク情報」→ セキュリティグループの編集画面から、`IPv4v6-SSH`を追加で選択・適用

これで無事に接続できるようになりました。

## 後日談:Webサイト公開時にも同じ罠にハマった

このトラブルの後、Nginxをインストールしてサイトを公開しようとしたところ、今度は`http://(IPアドレス)`にブラウザでアクセスしても「応答時間が長すぎる」というエラーになりました。原因はまったく同じ構造で、**HTTP/HTTPS用にも`IPv4v6-Web`という専用のセキュリティグループが別途必要**でした。

つまり、ConoHa VPS 3.0では用途ごとに専用のセキュリティグループを個別に追加する必要があり、`default`(All許可)だけでは実質的に何も通らない、という仕様だったわけです。

## 公開鍵認証への切り替え

接続できるようになった後、セキュリティを高めるために、パスワード認証から公開鍵認証への切り替えも行いました。

### 手順

1. 手元のパソコンで鍵ペアを作成する
```powershell
ssh-keygen -t ed25519
```
2. 公開鍵をサーバーに登録する
```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@(IPアドレス) "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```
3. サーバー側で`sshd_config`を編集し、パスワード認証を無効化する
```bash
sudo nano /etc/ssh/sshd_config
```
```
PasswordAuthentication no
```
4. 設定を反映
```bash
sudo systemctl restart ssh
```

**この作業中は、今繋がっているSSH接続を切らずに、別のウィンドウで新規接続をテストする**のが鉄則です。万が一設定を間違えても、元の接続さえ生きていればいつでも復旧できます。実際、再起動を挟んでも公開鍵だけでログインできることを確認できました。

## つまずきポイントのまとめ

| つまずいたこと | 原因 | 学んだこと |
|---|---|---|
| SSH接続がタイムアウトし続けた | ConoHa VPS 3.0では、SSH専用のセキュリティグループ(`IPv4v6-SSH`)を別途追加する必要があった | 「All許可のグループがあるから大丈夫」と思い込まず、公式のヘルプ・仕様を確認する |
| Webサイト公開時にも同じ症状が再発 | HTTP/HTTPS用の専用グループ(`IPv4v6-Web`)も別途必要だった | 用途ごとに専用グループが必要という仕様を先に知っていれば、切り分けの時間を大幅に短縮できた |
| 原因の切り分けに時間がかかった | サーバー内部・自分のネットワーク・外部ツールと、正常な箇所ばかり確認していた | 「全部正常なのに繋がらない」ときは、サービス提供元特有の仕様(見落としがちな追加設定)を疑う |

一つ一つの原因は判明してみれば単純でしたが、「サーバーも自分の環境も両方正常」という状況から答えにたどり着くまでが本当に大変でした。分かってしまえば、ConoHa VPSを使う人には共通する重要な情報だと思うので、同じ症状で困っている人の助けになればと思います。
