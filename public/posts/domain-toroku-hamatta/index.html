ドメイン取得でハマった話(.com vs .dev、謎の無料オプション、認証メール迷子事件)

2026.08.29

VPSでサイトを公開できるようになった後、次にやったのが独自ドメインの取得でした。「IPアドレスの数字を打つ代わりに、覚えやすい名前でアクセスできるようにする」だけの作業のはずが、想像以上に長い道のりになったので記録しておきます。

そもそもドメインは必須なのか

結論から言うと、サイトを表示させるだけなら不要です。実際、IPアドレス(xxx.xxx.xxx.xxx)のままでもサイトは正常に公開できていました。

ただし、以下を考えると事実上必須でした。

  • HTTPS化(Let’s Encryptによる無料SSL)は、ドメインがないとそもそも証明書を発行できない
  • Google AdSenseの審査も、通常はドメインが前提の要件になっている
  • IPアドレスのままだと、読者から見て単純に怪しい・覚えにくい

.com か .dev か迷った話

技術者向けのブログなので、最初は.dev(エンジニア界隈で人気、Google運営)も候補にしていました。ただ調べてみると、料金にかなり差があることが分かりました。

ドメイン 初年度 2年目以降(毎年)
.com 数百円台 千円台後半
.dev 三千円台 三千円台

年間で見ると.devは.comのおよそ2倍。加えて.comは世界的に最も認知度が高く、収益化(広告・アフィリエイト)も見据えているなら一般読者にとって馴染みのある.comの方が無難と判断し、こちらに決めました。

「無料」の罠

申し込み画面で、ドメイン費用が0円になっている表示が出て一瞬喜びましたが、よく見ると別のサービス(AIでサイトを自動生成するオプション)とのセット契約になっていて、翌月から月額2,000円台の請求が発生する仕組みでした。

AIホームページパック
ご契約開始月が無料  0円
翌月以降 2,855円/月

今回はすでに自分でHugoで作ったサイトがあるので不要な機能です。申し込み内容から該当オプションを削除して、通常料金での申し込みに切り替えました。

⚠️ 教訓:「0円」の表示を見たら、その根拠(何かとのセット契約になっていないか)を必ず確認する。特に「翌月以降」という小さな注記は見落としやすい。

認証メールが見つからない事件

ドメインの決済は完了したのに、管理画面のどこを見ても「ご契約はありません」と表示され続けるという事態になりました。これはかなり焦りました。

原因を切り分けるため、以下を順番に確認しました。

  1. 「ドメイン一覧」を確認 → 表示されない
  2. 「ネームサーバー設定」を確認 → 「ご契約はありません」
  3. 登録メールアドレスに認証メールが来ていないか確認 → 迷惑メールも含めて探したが、最初は見つからず
  4. 画面右下に**「未申請のドメインがあります」**という通知を発見、申し込みカート画面を確認すると「このドメインはすでにお申込み済みです」という表示を確認

結果的に、決済(お金の支払い)と、契約の正式な確定は別の手続きだったということが分かりました。数日待っていたところ、以下の件名のメールが改めて届きました。

【重要】ドメイン情報認証のお願い

これはICANN(ドメイン管理の国際機関)のポリシーに基づく、登録者情報のメールアドレス確認手続きでした。メール内のリンクをクリックして初めて、正式に「契約中」というステータスに切り替わりました。

⚠️ 教訓:ドメイン購入直後に管理画面で契約が確認できなくても、慌てて何度も申し込み直したりせず、まず登録したメールアドレス(迷惑メールフォルダも含めて)を確認する。認証メールは即時ではなく、後日届く場合もある。

DNS設定(Aレコード)の追加

契約が正式に確定した後、ようやく本題のDNS設定に進めました。「DNSレコード設定」というメニューから、以下の2行を追加しました。

ホスト名 TYPE VALUE
(空欄) A サーバーのIPアドレス
www A サーバーのIPアドレス

これは「noluckblog.comという名前でアクセスがあったら、このIPアドレスのサーバーを見に行ってください」という道しるべを設定する作業です。wwwありのパターンも同時に設定しておくと、どちらの書き方でアクセスされても対応できます。

設定を確定させる際、ネームサーバーの変更も同時に必要という案内が出てきました。これも「そういう仕様なのか」と一瞬戸惑いましたが、案内された先はドメイン管理会社自身が公式に用意しているネームサーバーだったため、そのまま変更を承諾して進めました。

VPS側(Nginx)の設定も合わせて変更

DNS側の設定だけでは不十分で、サーバー側の設定もIPアドレス指定からドメイン名指定に書き換える必要がありました。

server {
    listen 80;
    server_name noluckblog.com www.noluckblog.com;
    root /var/www/yourlog/public;
    index index.html;
}

server_nameの行を書き換えてsudo systemctl restart nginxで反映。これでドメイン名でアクセスされたときも正しくサイトが表示されるようになりました(反映自体はDNSの伝播を待つ必要があり、最大72時間かかるとの案内あり)。

つまずきポイントのまとめ

つまずいたこと 原因 学んだこと
「無料」のドメインに気づいたら月額課金が付いていた 別サービスとのセット契約 「0円」表示は必ず内訳・注記を確認する
決済後も契約が管理画面に反映されない メールアドレスの有効性認証が別途必要だった 決済完了 ≠ 契約確定。認証メールを確認する習慣をつける
DNS設定にネームサーバー変更が必須だった ドメイン管理会社の仕様 案内文はよく読む、公式のネームサーバーへの変更なら心配しなくてよい
設定変更後、すぐにサイトが表示されない DNSの伝播に時間がかかる(最大72時間) 反映されなくても焦らない、失敗ではなく仕様

VPSのセキュリティグループのときと同じく、今回も「エラーの正体が最初は全く見えず、1つずつ確認して初めて原因にたどり着く」という経験になりました。地味な作業ですが、こういうインフラ・ネットワークまわりのトラブルシューティングの積み重ねが、一番実践的な学びになっている気がします。
