HTTPとHTTPSの違いを、実際のエラーから理解する

2026.09.06

「HTTPSの方が安全」ということは知識として知っていましたが、実際に「httpsで接続できません」というエラーに直面したことで、初めて仕組みとして理解できたので整理します。

HTTPとHTTPSの基本的な違い

HTTP HTTPS
意味 通信内容がそのまま(平文)でやり取りされる 通信内容が暗号化される
ポート番号 80 443
見分け方 鍵マークなし、「保護されていない通信」の警告 鍵マーク表示
必要なもの 特になし SSL証明書

なぜ暗号化が必要なのか

HTTP(暗号化なし)では、通信内容が第三者に読み取られたり、途中で改ざんされたりするリスクがあります。例えば、公共のWi-Fiでログイン情報を送信する際に、HTTPのままだと第三者に盗み見られる可能性がある、という説明はよく見かけますが、実感として理解できていたわけではありませんでした。

実際に直面したエラー

サイトマップをSearch Consoleに登録しようとした際、hugo.tomlのbaseURLが

baseURL = "https://noluckblog.com/"

となっていました。しかし、このときサーバー自体はまだHTTPでしか公開しておらず、SSL証明書を導入していませんでした。 ブラウザで直接

https://noluckblog.com

にアクセスすると、

接続できません

という、はっきりしたエラーになりました。この体験で、「HTTPSは、https://と書けば自動的に使えるものではなく、サーバー側にSSL証明書を用意して初めて使える機能」ということが、実感として腑に落ちました。

SSL証明書とは何なのか

証明書は、簡単に言うと**「このドメインの持ち主が発行を許可した、暗号化通信のための鍵」**です。これが無いと、ブラウザは暗号化通信を開始できません。

今回はLet’s Encryptという無料の認証局から証明書を発行してもらいました。

sudo certbot --nginx -d noluckblog.com -d www.noluckblog.com

このコマンド1つで、証明書の取得と、Nginxの設定(listen 443 ssl;の追加など)まで自動で行われました。

証明書取得後に変わったこと

  • https://noluckblog.comで鍵マーク付きにアクセスできるようになった
  • http://でアクセスしても、自動的にhttps://にリダイレクトされるようになった(Certbotが設定してくれた)
  • Search Consoleのサイトマップも、正常に取得できるようになった

学び

「HTTPSにする」という作業は、単に設定ファイルの記述を変えるだけでは完結せず、証明書という実体を用意して、初めて成立する仕組みだと理解できました。baseURLの記述と、サーバーの実際の状態が食い違っていたために起きたエラーでしたが、逆にこのエラーのおかげで、普段何気なく見ている鍵マークの裏側を、初めてきちんと理解する機会になりました。
